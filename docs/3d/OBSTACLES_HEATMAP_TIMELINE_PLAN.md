修订日期：2026-11-12。性质：增量实施计划及配套单agent提示词；本版核实并处理外部审查的B1–B4、S1–S3、F1–F9，处置索引见第11节。本文不表示所列功能已实现。第10节可直接交给执行agent。

## 1. 交付目标与实际起点

在现有RollingStone3D上完成一个连续流程：设置障碍物 → 冻结本批环境 → 前两次实时预览 → 其余试验后台计算并逐步汇总轨迹 → 查看全批轨迹、路径热图和首次触碰挡板热图 → 选择试验并拖动时间轴回看 → 保存并重新打开结果。

## 2. 总体结构：一份环境、逐试验记录、只读显示

各项功能共用数据链：`SceneDraft → FrozenEnvironment → Trial::step/接触事件 → 每步统计＋MotionRecorder → TrialArchive/分析快照 → 全批绘制＋PlaybackController`。

- `FrozenEnvironment`：实际地形、ObstacleSet、挡板配置及environment_hash。每批只生成一次障碍布局，所有trial、前两次预览、headless和结果重载使用同一份几何。
- `MotionRecorder`：从数值层获取快照，所有trial一视同仁；不从渲染帧或相机事件反推运动。记录降采样不改变每步统计。
- `TrialArchive`：按run_id/trial_id索引实际形状、记录区间、终止原因和分块运动数据；全部trial均有目录条目，生成失败可以是无运动记录的条目。
- `RouteAccumulator`：由相邻物理步质心线段计算全域xy经过格，正常完成时合并该trial的去重集合；与原坡脚Statistics并行更新。
- `FirstBarrierContactCollector`：只收集落石—目标挡板接触，从每个trial最早有效接触子步形成一次事件；记录实际接触点和当时挡板姿态，独立于轨迹降采样及渲染刷新。
- `PlaybackController`：只读档案，输出显示姿态；不能调用Trial::step、改变随机数状态、覆盖当前物理世界或重新计概率。
- `AnalysisView`：主线程获取版本化只读目录/计数快照，不在持有Session锁时写盘、上传GPU或复制全部轨迹。结果目录是持久化真相，UI缓存允许淘汰并重载。

现有BatchEvent的scene/snapshot是回调期间有效的借用指针；跨线程或延后保存必须复制数据或改成有明确生命周期的只读所有权，不能直接把裸指针放入事件队列。目录追加按trial_id去重且可追赶版本，即使UI错过几次刷新，也不能漏掉中间完成的trial。

物理保持固定步长及`JobSystemSingleThreaded`，所有trial顺序执行。子步编号由`PhysicsStepListener::OnStep`的first/last标记及本次Update内计数建立，当前每Update有4个collision_substep；无活跃体时没有OnStep，不能凭空递增。事件采集依赖此单线程约束，未来换作业系统须另做同步设计。与ElasticSupport明确监听器顺序和前后子步归属，读出后立即复制；受控文件读取线程可预取时间轴数据，raylib/GPU操作留在主线程。

## 3. 功能一：路径上的随机固定障碍物

### 3.1 参数与首版形状

首版障碍物采用零圆角刚性长方体，长、宽、露出高度及绕z轴角度随机；不复用落石定体积采样器。其作用是提供真实碰撞表面，不能只在画面上贴装饰物。

| 配置 | 首版默认与校验 |
| --- | --- |
| enabled/count | 旧配置缺项时disabled，行为不变；新演示配置enabled、count=40，允许0～500且为整数 |
| obstacle_seed | 独立uint64，默认20261112；0是合法种子；相同种子与相同环境输入生成相同布局 |
| 尺寸模式、长/宽区间 | 默认relative_to_r，各0.30r～0.80r；r为该批固定的落石半径参数。允许absolute_m输入原有小尺寸；冻结时换算成实际米数。数值正且有限、下界不大于上界 |
| 露出高度区间 | 默认0.10r～0.40r，定义为“足迹内最高地形点以上的高度”；不是埋入后盒体的总高度。absolute_m时直接输入米数 |
| 方位角 | [0,360)度均匀抽样；长宽高均用现有Random的确定性均匀抽样 |
| 布置区域 | 默认x下界xMin+5，上界xEnd−5；挡板启用时上界再取min(该值,挡板保留区最小x)。y区间为[releaseY_min−3r,releaseY_max+3r]与[yMin+1,yMax−1]的交集；自定义区域明确标注，空集报错 |
| 间距/埋深 | 两障碍水平足迹最小距离0.20m；底面埋入0.03m；不可用负数 |
| 材料 | 接触对摩擦0.45、恢复系数0.20，允许输入有效范围；这是示例设置，不表示材料已标定 |
| 构造预算 | 每个目标障碍物最多200次候选，共count×200次；接受数量必须等于count，不能静默少放 |

界面增加启用、数量、区域、尺寸区间、材料、seed，以及“重新生成障碍物”。更改参数只改草稿，点击应用/重新生成后更新空闲预览；批次运行或暂停期间禁止应用环境修改。换一个障碍seed不改变主seed、落石形状/物性/释放参数的随机流。

独立新增组合演示配置：沿用r=2、V=7、N=100，释放x∈[10,12]m、y∈[−2,2]m，启用挡板及40块障碍；其他几何/材料默认沿用当前配置。不修改用户的default.ini或自动把固定释放点随机化。固定释放点也有随机形状/姿态，不能预先断言必无分散；用实测展示轨迹变化。演示至少有可复现的障碍接触及触板事件，记录使用的seed与次数，不把该演示的挑选过程当统计结论。

### 3.2 布置与冻结算法

1. 复用现有mix/Random，增加独立`obstacleDomain=0x4F00000000000000`；候选流种子为`mix(obstacle_seed ^ obstacleDomain)`。不消费kDomain/propertyDomain/shapeDomain的随机数。布局算法版本写为`fixed-box-obstacles-v1`。
2. 按固定顺序抽x、y、yaw、length、width、exposed_height。用旋转后的完整足迹检查区域与地形边界，不能只检查中心。
3. 排除整个释放x/y区间向四周扩张`r+0.5m`形成的保留区，以及挡板初始足迹及1m保留区。保留区属于布局输入并参与哈希；若当前挡板已有明确运动限位/扫掠区域，也排除该区域。与已有障碍足迹按真实旋转矩形检查间距。
4. 复用或提取`terrain.cpp`已有`clipTriangle`及平面求高逻辑，将旋转矩形足迹与实际地形三角片的xy投影相交，在交多边形全部顶点求z_min/z_max。等价的点集合必须包含足迹角点、内部三角片顶点及所有边—边交点；只取前两类会漏极值，首版不采用该近似。处理共线、重复点、零面积交集，先用AABB筛片。设base_z=z_min−0.03、top_z=z_max+exposed_height；埋入地形是有意锚固。
5. 验证实际尺寸/位置/朝向有限且可创建Jolt形状；默认总高上限2r，absolute_m模式可输入明确米值，均写入冻结配置。超限拒绝并计原因；不得把高程起伏造成的总高误当露出高度。
6. 按接受顺序赋稳定obstacle_id（与地形/落石/挡板ID不冲突），保存实际顶点/面、变换、尺寸与材料。总预算耗尽则整批在第一个trial前失败，报告已接受数、失败原因统计和seed；保留此前结果，不按较少数量继续。
7. 冻结ObstacleSet并生成obstacle_hash；每个PhysicsScene只引用该不可变集合。freezeConfig可做有哈希的缓存重建，不能在每个trial里随机重新布局。改变N或GUI预览数不应改变布局。

相同seed且相同配置重复启动一批会得到相同障碍；要获得新布局，用户显式点击重新生成（例如seed←mix(seed)）或输入新seed。新一批不自动掺入墙钟随机数。保存/加载场景必须保留这一规则。

### 3.3 物理与显示接入

- **F1前置容量修改**：当前`system.Init(16,0,1024,1024,…)`不足以放40块障碍。令maxBodies=max(16,count+8)，或向上取2次幂；maxBodyPairs起始取max(1024,16×maxBodies)，maxContactConstraints取max(1024,32×maxBodies)，校验整数溢出和引擎上限。这是待压力验证的容量预算，不是无溢出证明；记录实际值与预分配内存。检查创建失败及Update错误，不能丢弃碰撞继续运行。
- 每个障碍为`EMotionType::Static`、零凸半径；全部地形/障碍/挡板/落石加入后再调用`OptimizeBroadPhase()`，仅调整构造时机，无需逐步调用。碰撞后固定体变换完全不变。
- SceneModels渲染与Jolt使用同一份几何/变换；支持障碍选择高亮和只读ID/尺寸/材料信息，不要求自由拖拽编辑器。
- **首版明确障碍不与挡板碰撞**：保留只允许含落石层1的接触对，障碍层0、弹性挡板层2仍相互过滤。障碍不限制支座位移；初始及已知有限扫掠区保留，若支座无有限限位，不能承诺任意大位移仍不穿越障碍，界面说明该建模范围。
- 按对象ID定义对称材料表：rock–terrain取地面μ/e，rock–obstacle取障碍μ/e，rock–rigid_barrier取挡板μ/e，rock–elastic_barrier取挡板μ且e=0。当前落石0.731/0.817是用于检验组合规则的占位值，不是实际接触材料；新对象不得走顺序相关的非落石默认分支。回调先确认恰有一方rock，再分类，对调body顺序同结果；未知/被过滤接触明确忽略或诊断。
- 障碍上表面支撑参与现有静止和滚阻支撑处理，复用现有物理规则；垂直壁面不能凭对象类别被当作水平承托。不得将障碍冲量错误注入弹性挡板支座。
- 首次构造时检查实际初始落石与所有障碍无穿透；配置导致冲突则报告该试验失败，不偷移释放点或改变抽样值。
- 开关障碍应只改变环境与碰撞结果；落石实际几何、物性与初态随机样本在同主seed下保持相同。碰撞后的轨迹当然可以改变。

## 4. 功能二：全批轨迹及路径热图

### 4.1 何时显示哪些内容

- 前两次保持现有实时动画。第二次结束时显示当前已得到的完整轨迹；后台trial结束后追加其全程折线，自动刷新不超过每秒4次，整批结束立即刷新。
- 剩余N−2次不自动逐个播放石块运动；追加静态轨迹和更新热图即可。用户主动用时间轴播放已记录试验，不影响后台继续计算。
- 提供“全部轨迹／热图／叠加”三种模式，轨迹透明度、显示开关、trial选择和自动/固定相机。默认展示本批所有有有效记录的轨迹，不继续只保留最后两条，也不从每条轨迹头部删除数据。
- 失败、超时、取消的已知片段以区别于正常轨迹的线型/颜色显示，终点标注状态；无初态的生成失败在列表中显示原因，不绘制虚假线段。
- 首版不做历史多批合并、复杂筛选后的概率重算或防护方案对比；选中trial只高亮，不改变热图分母。

### 4.2 热图的统计口径

默认新热图是**全地形范围的xy路径经过概率**：范围为[xMin,xEnd]×[yMin,yMax]，格宽默认1m，按全部高度的质心轨迹在xy投影中穿格统计；每次trial对同一xy格最多计1次。它回答“该水平位置上方曾有落石经过”，不表示在地面接触、停留时长、撞击力或危险等级。

统计明确从t=0起，包括首次触地前的空中段和释放格；本版不增加“首次触地后才统计”的另一口径。固定释放点出现100%释放格是正确信息，可用放大/轨迹叠加观察下游分散，不能删掉释放段来美化热图。横坡专用验收配置显式选择已有的toe_min，原配置height_reference不自动改变。

使用相邻物理步的质心线段投影作二维穿格与逐trial去重；域外终止段先按现有吸收边界裁剪。不从降采样轨迹折线、像素透明度、轨迹点数量或三维体素概率相加得到热图。

旧坡脚0～10m统计保持原有范围和高度基准。界面可切换“全路径xy”“坡脚xy/xz”，各自清晰标注范围/高度/分母；旧统计未覆盖的地方不是零概率。不同图层的计数和图例不得混用。

对目标N、正常完成数C、某格正常完成试验命中H：

- 整批完整且所有输出成功：正式概率p=H/N，固定0～1色标，显示百分比及H/N；零命中与未覆盖区域区分。
- 计算中或存在失败/取消：正式概率仍为空，显示“累计下界H/N，已正常完成C/N”，并可查询范围`[H/N,(H+N−C)/N]`；该范围不是置信区间。不能用H/C当作最终总体概率。
- 正常完成且未进入统计域的trial仍在分母中；每格概率之和无需等于1。
- 诊断轨迹可以显示失败片段，但其访问不并入正常完成计数H。图例解释这一差异，避免看见一条失败路径却误以为概率计算漏掉它。

三维视口把xy热图按实际三角地形贴合绘制，使用深度偏移避免闪烁；这是路径投影图层，不能改变碰撞地形。保留俯视二维图例/查看方式。障碍物用实体颜色保持可辨，不能被热图伪装为另一种材料。

### 4.3 首次触碰挡板的位置热图

本功能回答“各次试验首次与挡板发生数值接触的位置”，统计几何触碰或已实际执行的接触响应。预测约束可能在仍有正间隙时施加响应，因此保存间隙/方法，图例说明这是当前求解器的数值接触，不能声称物体表面恰好零间隙。不用质心跨板位置代替触点。每trial只产生一次首次事件，持续/反弹后接触不重复计数；事件保存barrier_id，随机小障碍物不是挡板。

**事件确认与时序：**

1. 在物理接触层按明确的rock/barrier对象ID识别双方，不假定挡板一定是静态体或固定为body1。刚性及已有弹性挡板都要支持；障碍—挡板或地形—挡板接触不能触发此事件。
2. 回调只是候选。当前slop=min(1e−3,1e−4r,0.01innerRadius)，r=2时至多0.2mm；预测距离则为刚性20mm、弹性50mm。负穿深及OnContactAdded不能给出已求解冲量。Jolt的CCD还可能撤销此前已通知的候选，所以单凭回调、接近速度或EstimateCollisionResponse均不确认命中。
3. 明确分级判据：`geometric_touch`为被保留接触对的真实窄相位间隙≤该trial slop，记录有限几何容差；`solved_constraint`为该对子步最终压缩法向冲量大于记录阈值，允许正间隙；`resolved_ccd`为实际执行的CCD响应分支确认命中，保存fraction及实际响应。初始冲量噪声阈值取max(1e−6 N·s,1e−8×m_rock×1m/s)，F0用10倍上下变动做敏感性检查并记录最终值；边界歧义保留未知。正间隙且无实际响应的预测候选排除。`speculative_with_approach`/`estimated_response`只作诊断候选，不混入H_b。
4. 按物理step与collision_substep排序，收集最早已确认子步内的全部有效候选后再锁定，不能按并发回调先后挑第一个点。记录`time_lower/time_upper`、子步编号、检测方法及容差；没有精确TOI时只宣称子步精度，不能拿0.01s绘图记录时间当首次接触时刻。
5. 从挡板一侧读取世界接触点p_b，并使用**同一事件时刻**挡板中心c_b和旋转R_b，计算`p_local=transpose(R_b)*(p_b-c_b)`。当前盒体局部x为厚度、y为宽度、z为高度；保存当时落石/挡板姿态及原始点。移动或转动挡板不能用初始位置或下一个显示帧的姿态换算。

**F0先完成的只读求解观测适配：**

- 不假定存在公共的“读取该接触已求解冲量”API。本地固定源码的`ContactConstraintManager::StoreAppliedImpulses`可读取各点最终`mNonPenetrationConstraint.GetTotalLambda()`；`PhysicsSystem::JobResolveCCDContacts`可区分实际响应分支与撤销/跳过的CCD候选。在这些已经核对的位置做最小只读事件出口，保存body/subshape、子步、接触锚点、法向、最终冲量/CCD fraction；普通约束与CCD两条路径都覆盖。不能在每次迭代中重复累加最终lambda。
- 实施授权限于项目托管的观测补丁及构建适配：锁定上游SHA不变，校验原文件hash后在构建目录生成所需源码副本；缓存`.deps3d/JoltPhysics`保持原样。构建只编译一份对应实现，补丁、输入/生成文件hash、上游SHA和`observer_version`进入构建审计及结果清单。适配声明“上游版本＋观测补丁”，不冒称完全未修改的上游二进制。禁止通过增大slop、修改碰撞参数或改变求解顺序让热图有数。
- 观测点在当前单线程作业系统内同步复制小记录，回调内不写盘、不调用锁定BodyInterface、不改变刚体/约束；缓冲溢出明确报诊断。CCD保存查询所用姿态与fraction，若双方姿态不能可靠还原则保留时间区间及原因，不用下一显示帧补造。
- F0用低速触碰、刚性高恢复正间隙反弹、弹性响应、预测擦过、CCD撤销/实际命中及同时接触地面六类用例验证；普通高速刚性/弹性命中必须得到确认事件，不能以全标unresolved通过。对照无补丁、补丁关闭记录、开启记录，运动/已有统计在既有容差内一致。未通过时这是需修复的接触观测阻塞，不进入依赖它的正式统计实现。
- 未知仍有合法用途：损坏/丢失观测或阈值歧义标contact_unresolved；若存在更早的未决候选，后来的确认点不能冒称“首次”，保留为诊断。部分数据按下面的上下界继续显示，不把未知当未碰到。

证据来自固定版本的[ContactListener](https://github.com/jrouwe/JoltPhysics/blob/v5.3.0/Jolt/Physics/Collision/ContactListener.h)与[EstimateCollisionResponse](https://github.com/jrouwe/JoltPhysics/blob/v5.3.0/Jolt/Physics/Collision/EstimateCollisionResponse.h)，以及本地上述两处求解实现；估算接口对同时多体碰撞有明确准确性限制。这里的观测适配是本次实施要求，尚未实现或运行验证。

**唯一代表位置与网格：**

- 默认展示挡板局部“宽度×高度”投影：`u=local_y+width/2`、`v=local_z+height/2`，范围[0,width]×[0,height]，默认格宽/格高各1m，可输入。10m×5m挡板为50格；可切换计数、散点叠加或概率，不做核平滑来伪造连续热点。格边界半开、最后外边界闭合，尺寸不能整除时保留末端小格。
- 单个首次接触子步有多个同时接触点时，先按声明并记录的局部距离容差去重，再取其(u,v)算术平均作为该次事件的代表位置，落入一个格。它代表“该子步首次接触区域”，不声称几何上一定只有一个接触点；同时保存原始点数与所有点，避免数据不可追溯。
- 保存原始点local_x和front/back/side/top/bottom/mixed分类。默认图包含所有表面的宽高投影，图题明确“含背面及边缘触碰”，不得伪称全是迎石正面命中；三维实际触点用原始点标记，不把投影平均值当作真实表面点。
- 仅允许在记录的数值容差内修正边界舍入；明显落在挡板尺寸之外、NaN或无法分类的点是诊断错误，不能直接夹进最邻近格伪造热点。

**分母、完整性与界面：**

- 正常完成且接触观测明确的试验数为C_b，其中首次命中数为B、正常未触板数为M，满足C_b=B+M。单格首次命中数为H_b；每次试验最多进入一个格，故所有格计数之和恰为B。后续失败/取消的已记录触点保留为诊断，但不并入正式H_b；contact_unresolved和未开始项属于未知，不冒充未命中。
- 完整批次且观测/写盘均成功时，默认色值为H_b/N，所有格概率和为B/N，即本批触板率。另提供明确标注的“已触板试验内的位置分布”H_b/B；B>0时其和为1，B=0时显示“不适用”，不能除零。首图不是接触力、能量或停留时长热图。
- 计算中、未确认、失败或取消时仍绘制计数及**概率下界热图**H_b/N，并显示逐格范围[H_b/N,(H_b+N−C_b)/N]、B/M/未知数。CSV的精确probability为空，display_value/lower/upper有值且probability_kind=lower_bound；这不是空白图，也不把下界冒称精确概率或统计置信区间。条件概率此时不作为全批正式结果。挡板禁用为不适用；完整且B=0时主图为零、条件图不适用。
- 不设置“N≥300才显示概率”的硬门槛。任何N>0均可显示有明确分母的经验频率/上下界；同时显示N、B、有效格数及分辨率1/N（条件图为1/B），小样本不宣称分布稳定。计数模式图例标次数，概率模式固定0～1，用户可以查看稀疏真实数据。
- 结果视图增加“首次触板”页、挡板轮廓、米制坐标、格值提示和B/N。两次预览后随正常完成trial增量刷新，整批结束与CSV核对；原路径热图保持独立。
- 点选热格列出对应trial_id；选择试验可“跳到首次触碰”，时间轴定位其事件区间并展示实际事件姿态/原始触点。时间不精确时显示区间。拖动和重复播放只读事件，不重复计数；热图仍表示整批结果，未来事件可在列表中存在，但三维事件标记仅在定位/经过对应区间时显示。

## 5. 功能三：逐试验可拖动时间轴

### 5.1 交互与状态

底部时间轴绑定当前选中的trial，单位为该试验开始后的模拟秒，范围为[0,t_recorded]。提供试验编号选择、开始/结束、前后一个记录帧、播放/暂停、0.25/0.5/1/2倍速和“跟随实时”。独立试验不拼成一条会让石头跳接的长轨迹。

- 空闲无记录时禁用；有记录后才能拖动，不能拖到尚未计算的未来。
- 用户拖动或选择历史trial时退出实时跟随，物理worker继续原状态；“暂停回放”与“暂停计算”是不同按钮、不同状态。
- 正在记录的trial允许查看已发布部分；结束时范围扩展至真实最后帧。生成失败无历史，滑块禁用并显示原因；超时/取消可回看已有区间。
- 时间轴获取鼠标拖动的优先权，拖出控件仍保持捕获到释放；不得同时转动相机或改变参数。切换试验、重置及关闭窗口要释放捕获。
- “跟随实时”只在前两次预览且有实时对象时启用；第3次起后台阶段禁用，保留所选trial和游标，允许读取已发布记录但不自动播放当前计算对象。后台结束后也不突然跳到最后一个trial。
- 所有轨迹/整批热图保持静态汇总；时间轴仅改变所选石块、所选轨迹已走片段高亮及相关动态挡板姿态，不随游标重算全批概率。
- 增加“跳到首次触板”；有确认事件时定位其时间区间并读取双方事件快照、显示原始接触点，无触碰/未记录/未确认时显示相应状态并禁用跳转。区间内没有精确时间时不能伪称精确到达某个时间点。

### 5.2 记录与显示重建

新增记录器有auto/显式间隔：auto在N<300时取0.01s、N≥300时取0.02s，并向上取整为dt整数倍；启动前显示实际间隔和容量估算，冻结后全批一致，不中途降频。每次均保存t=0、最终有效帧及接触类别变化前后一帧，突变可额外记录。规则写入版本，同物理步去重；逐步统计及独立首次触板事件不受此间隔影响，生成失败没有伪造t=0姿态。

首次触板事件快照独立于上述固定间隔记录，保留事件自身的step/substep及时间精度。跳转到事件时优先显示该快照；不能以相邻普通帧插值代替已经记录的接触姿态，也不能为了定位事件再次调用物理Update。

记录至少包含step/time、质心center、shapeOrigin、四元数rotation、速度/角速度、终止状态和可用的动态挡板状态。geometry仍保存为该trial实际顶点/面；显示变换遵循当前`shapeOrigin + rotation*(vertex−canonical_COM)`，不能把质心直接当形状原点。

读取时间t时用二分定位两帧。位置/显示标量线性插值，姿态做归一化最短弧SLERP（q与−q视为同姿态），接触类别等离散字段采用前一已记录状态；在真实记录时刻必须还原该帧。禁止越界外推、NaN姿态或以欧拉角直接线性插值。稀疏碰撞片段标注“显示插值”，不声称中间姿态满足重新求解的碰撞约束。

若当前基线含弹性挡板，回放必须读该trial同一时刻的BarrierSnapshot，不得配上另一次试验或当前实时挡板。旧结果缺挡板历史时明确提示该动态部件不可回放，不能伪造成静止或重新积分来补。

既有`--replay`用于重新积分/一致性验证，继续保留。新增`--view-results <目录>`使用独立档案读取器；不直接复用loadReplay重积分路径或其k≤100、faces≤196硬编码限制。按格式版本/实际几何计数及有记录的安全容量限值校验，超限明确报错。旧CSV仅按实际帧浏览；缺失轨迹或stride=0的旧结果明确“无历史记录”。

结果格式与配置schema升级时提供明确的旧版本读取分支；不能直接给旧scene补字段后再拿新算法哈希与旧run_config_hash硬比。旧文件缺障碍字段只在已识别的旧schema中解释为“无障碍”；新schema缺必需障碍数据应报损坏。哈希至少区分物理配置、实际环境、采样器/源码版本和显示记录设置，避免改显示帧率影响样本身份。

首次触板事件独立保存，即使trajectoryStride=0或普通采样很稀也不丢失。旧结果无事件时显示“未记录”，不从质心轨迹/最终touched反推首次点。contact_unresolved进入未知数及上下界，分析标记不完整但仍有可查询的下界图；simulation_complete不等于contact_analysis_complete。

障碍在试验开始前导出。使用现有pending目录和最终提交完成清单机制，新增文件全部flush/close及校验成功后才宣布完整；分析文件写入失败不能仍显示“完整结果”。运行中只发布已完成写入的块，目录重命名时处理读取句柄，避免播放器锁住Windows文件导致整批无法完成。

必须修改`RunOutput::finish`中硬编码的FILES_COMPLETE.txt文件清单，以及`RunOutput::diagnose`的io_error概率文件处理名单。优先用同一结果文件注册表生成完成清单、读取校验和失败清理：包括障碍三表、路径热图、首次触板三表、motion.bin及motion_index.csv，不能只加分析CSV。FILES_COMPLETE代表文件事务成功，不代表全部N次有效；取消/部分失败可成功保存有明确下界的部分结果。写盘失败保持.pending/INCOMPLETE，已写完的原始块可诊断读取，但所有旧/新概率文件必须失效；不能因删除失败再保留complete=1。逐个新增文件及最终manifest/rename阶段注入失败验证。

### 6.2 全批数据不等于全部常驻内存

所有trial都记录并可选择；内存只留当前块、简化绘制轨迹、必要统计和有限回放缓存。禁止用“只保留最近100条”或默默截断早期轨迹满足性能。

- 记录层采用显式字段序列化，不直接写含填充/指针的C++结构体。保留double世界位置/时间与足够姿态精度，明确字节序、版本和每种块长度；无需新增数据库/压缩库。
- 历史缓存默认上限256MiB，可配置；磁盘读写按有界块进行，检查偏移/尺寸整数溢出及文件截断。高频回放请求用请求序号丢弃过期读取结果，不能让旧请求覆盖新游标。
- 以160B/帧估算，100×60s/0.01s约96MB；1000次显式0.01s约960MB，auto 0.02s约480MB，均未计索引、动态字段及额外事件。按最终编码/实际记录量报告，开始前展示估算；不能承诺固定文件大小。
- 事件密集时以实际物理步数估算上界：当前参数最多约3000万帧/1000次，每步至多一帧。开始前估计空间，写盘失败按结果事务处理；不得无提示地关闭记录或删除早期trial。
- 用可复现的折线简化/分级细节绘制全部trial，每条至少保留首尾和重要转折，默认总显示预算200万顶点；不能通过随机只画部分trial近似“全部”。简化仅影响绘制，统计和可加载历史保持完整。
- 优先复用现有static_lines/native_lines的批量绘制方式，已完成轨迹只在数据变化或细节级别改变时更新GPU缓存，不逐帧解析文件或重建全部折线。
- 原始历史写盘或缓存满时可以有界背压，但不得丢失trial记录；主线程不等长文件读取、不在每帧解析整份CSV。取消需在块边界响应，已写完整块仍可诊断浏览。
